Root Finding and the Bisection Method

Trap the root between two points where f changes sign, then halve the interval again and again. Slow, but it never fails, and it tells you exactly how accurate it is.

The idea in one picture

The curve crosses the axis somewhere: that x is the root.f is negative at a and positive at b, so the root is between them.Look at the middle point c. Which sign does f have there?Negative, like a. So the root is in the right half: keep it.Halve again: now f(c) is positive.Keep the left part. The bracket is 4 times smaller than at the start.Each step halves the bracket. The root can never escape.
In plain words
  • If f is below the axis at a and above it at b, it must cross in between
  • Test the middle; keep the half where the sign still changes
  • Repeat: the trap gets half as wide every time

The root-finding problem

  • Find xxx with f(x)=0f(x) = 0f(x)=0: a root of fff, or a zero; graphically, where the curve crosses the xxx-axis
  • Any equation can be rewritten: ex=3x  ⇒  f(x)=ex−3x=0e^{x} = 3x \;\Rightarrow\; f(x) = e^{x} - 3x = 0ex=3x⇒f(x)=ex−3x=0
  • Polynomials of degree ≥ 5 and most transcendental equations (sin⁡\sinsin, exe^xex, ln⁡\lnln mixed with powers) have no formula for their roots
  • Two families of methods: bracketing (bisection, false position) and open (fixed point, Newton, secant)

The bisection algorithm

  1. Start with [a,b][a, b][a,b] where f(a) f(b)<0f(a)\,f(b) < 0f(a)f(b)<0
  2. Midpoint c=a+b2c = \dfrac{a + b}{2}c=2a+b​; compute f(c)f(c)f(c)
  3. If f(a) f(c)<0f(a)\,f(c) < 0f(a)f(c)<0, the root is in [a,c][a, c][a,c]: set b=cb = cb=c
  4. Otherwise the root is in [c,b][c, b][c,b]: set a=ca = ca=c (if f(c)=0f(c) = 0f(c)=0, stop: ccc is the root)
  5. Repeat until b−a2<ε\dfrac{b - a}{2} < \varepsilon2b−a​<ε; the answer is the last midpoint
Pseudocode
input f, a, b, tol
if f(a)·f(b) > 0: stop (no bracket)
repeat up to N times:
    c ← (a + b) / 2
    if f(c) = 0 or (b − a)/2 < tol:
        return c
    if f(a)·f(c) < 0:  b ← c
    else:              a ← c

Each pass keeps the half of the bracket where the sign changes, so the root stays trapped while the bracket halves.

When bisection is fooled

  • Pole: 1/(x−1)1/(x-1)1/(x−1) changes sign at x=1x = 1x=1 without a root; bisection "converges" to the pole, and f(c)f(c)f(c) blows up
  • Double root: (x−1)2≥0(x-1)^2 \ge 0(x−1)2≥0, no sign change, bisection cannot start
  • Several roots: it finds one of them, not necessarily the one you want
  • Defence: plot or tabulate fff first, and check that ∣f(c)∣|f(c)|∣f(c)∣ really becomes small

When to use it

Bisection: method profile

Best case
  • Any continuous fff with one sign change in [a,b][a, b][a,b]: success is guaranteed
  • Cost is the same for every fff: ⌈log⁡2((b−a)/ε)⌉\lceil\log_2((b-a)/\varepsilon)\rceil⌈log2​((b−a)/ε)⌉ steps (20 for 10−610^{-6}10−6 on a unit interval); only a lucky exact hit f(c)=0f(c) = 0f(c)=0 ends earlier
  • Noisy, step-like or black-box fff: only the sign is used
Worst case
  • Even an easy, almost straight fff still takes 20 steps; false position needs 1 on a straight line
  • No sign change (double root (x−1)2(x-1)^2(x−1)2, both ends same sign): cannot start
  • A pole such as 1/(x−1)1/(x-1)1/(x−1): converges to the pole, not to a root
Best suited for
  • Monotone functions from data: thresholds, rates, calibration
  • Hard real-time code that needs a fixed, known running time
  • The first, safe phase of a hybrid solver that hands over to Newton or secant
Avoid when
  • f′f'f′ is cheap and you need many digits many times (use Newton, L9)
  • You need all roots of a polynomial, or roots of a system (L10)
  • fff is discontinuous or you have not plotted it

Rule of thumb: use bisection when failure is not allowed, and to get a safe starting bracket for a faster method.

Roadmap

Limitations, and where we fix them

Bisection is the benchmark: safe and predictable. Every later root-finding method keeps one of its strengths and removes one of its weaknesses.

What it does well (keep this)
  • Always converges once a sign change is found
  • Guaranteed error bound (b−a)/2n(b-a)/2^n(b−a)/2n at every step
  • Iteration count known in advance
  • Needs only the sign of fff: works on noisy or black-box functions

Summary

Key points
  • Rewrite as f(x)=0f(x) = 0f(x)=0; a sign change of a continuous fff on [a,b][a, b][a,b] traps a root (IVT)
  • Bisection: c=(a+b)/2c = (a+b)/2c=(a+b)/2, keep the half where the sign changes
  • Error bound ∣r−cn∣≤(b−a)/2n|r - c_n| \le (b-a)/2^n∣r−cn​∣≤(b−a)/2n; iterations n>log⁡2((b−a)/ε)n > \log_2((b-a)/\varepsilon)n>log2​((b−a)/ε)
  • Robust but slow (linear, rate ½); fails for double roots and is fooled by poles
  • Code: sign check + halving + stopping rule + iteration cap
