Why this lecture

The problem: temperatures inside a metal plate

The edges of a square plate are held at fixed temperatures. What is the temperature at the four marked interior points?

  • In steady heat flow, each interior temperature is the average of its four neighbours
  • Point 1: T1=14(100+0+T2+T3)T_1 = \tfrac14(100 + 0 + T_2 + T_3)T1​=41​(100+0+T2​+T3​), so 4T1−T2−T3=1004T_1 - T_2 - T_3 = 1004T1​−T2​−T3​=100
  • Four points give four linear equations; Cramer could manage this one
  • But engineers use a 100 × 100 grid: 10 000 unknowns. We need a method whose work grows like n3n^3n3, not n!n!n!

The method, step by step

Gaussian elimination, step by step

  1. Write the augmented matrix [A∣b][A \mid \mathbf{b}][A∣b]
  2. For column k=1,…,n−1k = 1, \dots, n-1k=1,…,n−1: check the pivot akk≠0a_{kk} \ne 0akk​=0
  3. For each row iii below it: mik=aik/akkm_{ik} = a_{ik}/a_{kk}mik​=aik​/akk​, then Ri←Ri−mikRkR_i \leftarrow R_i - m_{ik}R_kRi​←Ri​−mik​Rk​
  4. Now the system is upper triangular: xn=bn/annx_n = b_n/a_{nn}xn​=bn​/ann​
  5. Back substitution: xi=(bi−∑j>iaijxj)/aiix_i = (b_i - \sum_{j>i} a_{ij}x_j)/a_{ii}xi​=(bi​−∑j>i​aij​xj​)/aii​ for i=n−1,…,1i = n-1, \dots, 1i=n−1,…,1; check by substituting
Pseudocode
input A (n×n), b
for k = 1 … n−1:              # forward
    if a[k][k] = 0: stop (pivot)
    for i = k+1 … n:
        m ← a[i][k] / a[k][k]
        for j = k … n:
            a[i][j] ← a[i][j] − m·a[k][j]
        b[i] ← b[i] − m·b[k]
for i = n … 1:                # backward
    s ← b[i] − Σ_{j>i} a[i][j]·x[j]
    x[i] ← s / a[i][i]

Three nested loops in the forward part: that is where the n3n^3n3 comes from.

The method, step by step

Gauss–Jordan elimination, step by step

Eliminate above and below each pivot and scale it to 1. The left part becomes III and the right part is the answer.

  1. Write [A∣b][A \mid \mathbf{b}][A∣b] (or [A∣I][A \mid I][A∣I] to get the inverse)
  2. For column k=1,…,nk = 1, \dots, nk=1,…,n: divide row kkk by the pivot so that akk=1a_{kk} = 1akk​=1
  3. Clear column kkk in every other row: Ri←Ri−aikRkR_i \leftarrow R_i - a_{ik}R_kRi​←Ri​−aik​Rk​, for all i≠ki \ne ki=k
  4. After column nnn: [I∣x][I \mid \mathbf{x}][I∣x], so read off x\mathbf{x}x (no back substitution)
  5. With [A∣I][A \mid I][A∣I] you end with [I∣A−1][I \mid A^{-1}][I∣A−1]
Pseudocode
input M = [A | B]   # B = b or I
for k = 1 … n:
    if m[k][k] = 0: stop (pivot)
    R_k ← R_k / m[k][k]
    for i = 1 … n, i ≠ k:
        R_i ← R_i − m[i][k]·R_k
return right part of M

About n3n^3n3 operations: 50% more than Gaussian elimination, because it also clears the entries above the pivots.

The weakness: a tiny pivot destroys the answer

  • 0.0001x+y=10.0001x + y = 10.0001x+y=1,   x+y=2\;x + y = 2x+y=2: exact x=1.0001x = 1.0001x=1.0001, y=0.9999y = 0.9999y=0.9999

The method, step by step

The fix: partial pivoting

Before eliminating column kkk, bring the largest ∣aik∣|a_{ik}|∣aik​∣ (i≥ki \ge ki≥k) into the pivot position.

  1. For column kkk: find the row p≥kp \ge kp≥k with the largest ∣apk∣|a_{pk}|∣apk​∣
  2. Swap Rk↔RpR_k \leftrightarrow R_pRk​↔Rp​ (whole rows, including b\mathbf{b}b)
  3. Eliminate as before; now every ∣mik∣≤1|m_{ik}| \le 1∣mik​∣≤1
  4. If the largest ∣apk∣|a_{pk}|∣apk​∣ is 0, the matrix is singular: stop
  5. Back substitution as before
Added to the pseudocode
for k = 1 … n−1:
    p ← argmax_{i ≥ k} |a[i][k]|
    if a[p][k] = 0: stop (singular)
    swap rows k and p of [A | b]
    for i = k+1 … n:
        m ← a[i][k] / a[k][k]   # |m| ≤ 1
        R_i ← R_i − m·R_k

Multipliers at most 1 in size keep rounding errors from growing. It costs only comparisons, no extra arithmetic.

When to use it

Gaussian elimination: method profile

Best case
  • Dense systems up to a few thousand unknowns: 23n3\tfrac23 n^332​n3, under a second for n=1000n = 1000n=1000
  • With partial pivoting: reliable for almost every nonsingular matrix met in practice
  • Exact (up to rounding) in a fixed number of steps; no starting guess, no convergence question
Worst case
  • A zero or tiny pivot without pivoting: failure or garbage
  • Ill-conditioned AAA: pivoting cannot recover digits the problem itself loses
  • n=106n = 10^6n=106: 6.7×10176.7\times10^{17}6.7×1017 operations and 8 TB of memory
Best suited for
  • One system with a dense matrix
  • Inside other algorithms: each Newton step for a system (Lecture 10), least squares (Lecture 23)
  • Gauss–Jordan: inverses, RREF, rank
Avoid when
  • The same AAA with many right-hand sides (factor once: LU, Lecture 13)
  • Banded or tridiagonal matrices with the full algorithm (Thomas, Lecture 13)
  • Huge sparse systems (iterative methods, Lecture 14)

Rule of thumb: for one dense system, Gaussian elimination with partial pivoting is the default; switch only when the matrix has special structure.

Limitations, and where we fix them

Elimination is the workhorse, but it treats every matrix as dense and every right-hand side as new.

Summary

Key points
  • Forward elimination with multipliers mik=aik/akkm_{ik} = a_{ik}/a_{kk}mik​=aik​/akk​, then back substitution
  • Gauss–Jordan clears above and below: [I∣x][I \mid \mathbf{x}][I∣x], or [I∣A−1][I \mid A^{-1}][I∣A−1] from [A∣I][A \mid I][A∣I]
  • Cost about 23n3\tfrac23 n^332​n3 (Gauss–Jordan n3n^3n3), compared with e(n+1)!e(n+1)!e(n+1)! for Cramer
  • Partial pivoting (largest pivot, ∣m∣≤1|m| \le 1∣m∣≤1) prevents small pivots from destroying the answer
