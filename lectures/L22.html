Why this lecture

The problem: a spring that must not gain energy

A mass on a spring: position xxx, velocity yyy. Without friction it should oscillate for ever with the same energy x2+y2=1x^2 + y^2 = 1x2+y2=1.

  • Equations: x′=yx' = yx′=y,   y′=−x\;y' = -xy′=−x, start (1,0)(1, 0)(1,0): two unknowns, a system
  • Euler, h=0.1h = 0.1h=0.1, ten periods: energy grows from 1 to 517; the mass flies off
  • Heun: 1.016 (better, still drifting)
  • Orbits, circuits, molecules and epidemics need methods that stay accurate over thousands of steps

The method, step by step

RK4, step by step

  1. k1=h f(xn,yn)k_1 = h\,f(x_n, y_n)k1​=hf(xn​,yn​): slope at the start
  2. k2=h f(xn+h/2,  yn+k1/2)k_2 = h\,f(x_n + h/2,\; y_n + k_1/2)k2​=hf(xn​+h/2,yn​+k1​/2): midpoint, using k1k_1k1​
  3. k3=h f(xn+h/2,  yn+k2/2)k_3 = h\,f(x_n + h/2,\; y_n + k_2/2)k3​=hf(xn​+h/2,yn​+k2​/2): midpoint again, using k2k_2k2​
  4. k4=h f(xn+h,  yn+k3)k_4 = h\,f(x_n + h,\; y_n + k_3)k4​=hf(xn​+h,yn​+k3​): end point, using k3k_3k3​
  5. yn+1=yn+(k1+2k2+2k3+k4)/6y_{n+1} = y_n + (k_1 + 2k_2 + 2k_3 + k_4)/6yn+1​=yn​+(k1​+2k2​+2k3​+k4​)/6;   xn+1=xn+h\;x_{n+1} = x_n + hxn+1​=xn​+h; repeat
Pseudocode
input f, x0, y0, h, x_end
x ← x0;  y ← y0
while x < x_end − h/2:
    k1 ← h·f(x, y)
    k2 ← h·f(x + h/2, y + k1/2)
    k3 ← h·f(x + h/2, y + k2/2)
    k4 ← h·f(x + h, y + k3)
    y ← y + (k1 + 2k2 + 2k3 + k4)/6
    x ← x + h
return y

Works unchanged for systems if yyy and the kkk's are vectors.

The method, step by step

A predictor–corrector method, step by step

  1. Get y0,y1,y2,y3y_0, y_1, y_2, y_3y0​,y1​,y2​,y3​ (starting values) by RK4; compute f0,…,f3f_0, \dots, f_3f0​,…,f3​
  2. Predict yn+1Py^{P}_{n+1}yn+1P​ with the predictor formula
  3. Evaluate fn+1P=f(xn+1,yn+1P)f^{P}_{n+1} = f(x_{n+1}, y^{P}_{n+1})fn+1P​=f(xn+1​,yn+1P​)
  4. Correct: yn+1Cy^{C}_{n+1}yn+1C​ with the corrector formula (optionally repeat steps 3–4 once)
  5. Store fn+1=f(xn+1,yn+1C)f_{n+1} = f(x_{n+1}, y^{C}_{n+1})fn+1​=f(xn+1​,yn+1C​), shift the window of four slopes, repeat
Pseudocode (Adams–Bashforth–Moulton)
y[0..3] ← RK4 starting values
F[k] ← f(x[k], y[k]),  k = 0 … 3
for n = 3, 4, …:
    yp ← y[n] + h/24·(55F[n] − 59F[n−1]
                     + 37F[n−2] − 9F[n−3])
    fp ← f(x[n+1], yp)
    y[n+1] ← y[n] + h/24·(9fp + 19F[n]
                          − 5F[n−1] + F[n−2])
    F[n+1] ← f(x[n+1], y[n+1])
    err ≈ (19/270)·|y[n+1] − yp|

Two new fff values per step; the error estimate costs nothing.

When to use it

Runge–Kutta and predictor–corrector methods: method profile

Best case
  • RK4: smooth non-stiff problems; 6–8 digits with moderate hhh; self-starting, easy step changes
  • Adams–Bashforth–Moulton: expensive fff (2 evaluations per step) with a free error estimate
  • Systems of any size, written once in vector form
Worst case
  • Stiff problems: explicit methods need tiny steps
  • Milne for decaying solutions: unstable
  • Solutions with singularities or sudden jumps (fixed hhh)
Best suited for
  • Orbits, mechanics, circuits, chemical kinetics (non-stiff), epidemics
  • Adaptive pairs (RK45 / Dormand–Prince) in SciPy and MATLAB
  • Multistep methods in long simulations where fff is costly
Avoid when
  • Stiff systems (use implicit methods: backward Euler, BDF, Radau)
  • Very long Hamiltonian simulations (use symplectic integrators)
  • Fixed hhh when the solution changes scale (use adaptive step size)

Rule of thumb: start with an adaptive RK (RK45); if it takes absurdly small steps, the problem is stiff: switch to an implicit solver.
