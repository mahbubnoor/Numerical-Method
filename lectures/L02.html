Floating-Point Numbers

A computer keeps about 7 or 16 significant digits, in binary. That one fact explains why 0.1 + 0.2 ≠ 0.3, and sets the accuracy limit of every method in this course.

Floating-point form and significant digits

  • Normalised floating-point form (decimal): x=± 0.d1d2…dt×10ex = \pm\, 0.d_1 d_2 \dots d_t \times 10^{e}x=±0.d1​d2​…dt​×10e with d1≠0d_1 \ne 0d1​=0
  • The digits d1…dtd_1 \dots d_td1​…dt​ are the mantissa; eee is the exponent; ttt is the precision
  • Example: −347.62=−0.34762×103-347.62 = -0.34762 \times 10^{3}−347.62=−0.34762×103,   0.000123=0.123×10−3\;0.000123 = 0.123 \times 10^{-3}0.000123=0.123×10−3
  • Significant digits: all digits from the first non-zero digit onward. 0.0001230.0001230.000123 has 3; 2.5002.5002.500 has 4; 307030703070 has 3 or 4 (ambiguous: write 0.3070×1040.3070\times10^40.3070×104)
  • A computer stores only ttt digits, so most real numbers are replaced by a nearby representable one
Chopping

Cut off extra digits

23=0.666666⋯→0.6666\tfrac{2}{3} = 0.666666\dots \to 0.666632​=0.666666⋯→0.6666 (4 digits). Error up to one unit in the last place.

Rounding

Round to nearest

23→0.6667\tfrac{2}{3} \to 0.666732​→0.6667. Error at most half a unit in the last place. IEEE uses round-to-nearest, ties to even.

0.1 + 0.2, and how to compare floats

  • Neither 0.1, 0.2 nor 0.3 is exact; the rounding errors do not cancel
  • Never test floats with ==; test abs(a - b) < tol
  • Use a relative tolerance for large numbers: math.isclose(a, b)
  • Adding 0.1 ten times also misses 1.0: errors accumulate

float vs double: accumulation in C

  • Add 0.1 one million times. The true answer is 100000
  • float drifts by about 1000: wrong in the 3rd significant digit
  • double is wrong only after about 10 digits
  • Lesson: use double for numerical work; keep sums in double even if data are float

At the edges: overflow, underflow, special values

Overflow

Too big

10308×10=∞10^{308} \times 10 = \infty10308×10=∞ (inf). In Python, 2.0**1024 raises OverflowError; math.exp(1000) too.

Underflow

Too small

10−32010^{-320}10−320 is stored as a subnormal with fewer digits; below 5×10−3245\times10^{-324}5×10−324 it becomes 0.

NaN

Not a Number

0/00/00/0, ∞−∞\infty - \infty∞−∞, −1\sqrt{-1}−1​ in C give NaN. NaN ≠ NaN: even x == x is false.

🧠

When training "blows up"

A loss that becomes NaN or inf is usually overflow in exp (softmax) or a division by a tiny number. Libraries compute softmax as exi−max⁡xe^{x_i - \max x}exi​−maxx to avoid overflow: a numerical-methods trick.

Summary

Key points
  • Only fractions with power-of-2 denominators are exact in binary; 0.1 is not
  • Floating point = sign × mantissa × baseexponent, normalised; IEEE double has 53 significant bits
  • εmach=2−52≈2.2×10−16\varepsilon_{\text{mach}} = 2^{-52} \approx 2.2\times10^{-16}εmach​=2−52≈2.2×10−16: about 16 significant digits; rounding error ≤ ε/2 relative
  • Never compare floats with ==; use a tolerance, preferably relative
  • Use double; beware accumulation, overflow (inf), underflow and NaN
