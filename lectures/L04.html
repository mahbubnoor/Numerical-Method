Every numerical answer is wrong by some amount. We learn to measure that amount, predict how it grows, and avoid the one operation that destroys accuracy: subtracting nearly equal numbers.

Two sources of error in every computation

Lecture 2

Round-off error

  • From storing numbers with finitely many digits
  • Example: 23→0.6667\tfrac{2}{3} \to 0.666732​→0.6667,   0.1→0.1000000000000000055…\;0.1 \to 0.1000000000000000055\ldots0.1→0.1000000000000000055…
  • Grows slowly with the number of operations
  • Reduced by higher precision (double, not float)
+
this course

Truncation error

  • From replacing an infinite or exact process by a finite one
  • Example: e=1+1+12!+13!+14!=2.708333e = 1 + 1 + \tfrac{1}{2!} + \tfrac{1}{3!} + \tfrac{1}{4!} = 2.708333e=1+1+2!1​+3!1​+4!1​=2.708333, error 0.0099480.0099480.009948
  • Stopping an iteration, a finite step hhh, a cut series
  • Reduced by more terms, smaller hhh, more iterations

Total error = round-off + truncation. Making hhh smaller cuts truncation error but adds round-off error: a balance we measure later in this lecture and meet again in Lecture 19 (numerical differentiation).

Catastrophic cancellation

Subtracting two nearly equal numbers cancels their leading digits; only the noisy trailing digits survive.

  • 4-digit arithmetic: 1001−1000=31.64−31.62=0.02\sqrt{1001} - \sqrt{1000} = 31.64 - 31.62 = 0.021001​−1000​=31.64−31.62=0.02
  • True value 0.01580740.01580740.0158074: relative error 26.5%, from inputs accurate to 0.02%!
  • Rewrite (multiply by the conjugate): 11001+1000=163.26=0.01581\dfrac{1}{\sqrt{1001}+\sqrt{1000}} = \dfrac{1}{63.26} = 0.015811001​+1000​1​=63.261​=0.01581 (error 0.01%)
  • The subtraction itself is exact; it exposes the earlier rounding errors

Where this shows up in CSE and machine learning

📊

Variance in one pass

σ2=x2‾−xˉ2\sigma^2 = \overline{x^2} - \bar{x}^2σ2=x2−xˉ2 cancels badly when the mean is large: data near 10810^8108 give 22.0 instead of 22.5, and near 10910^9109 the result is pure noise (it can even be negative). Libraries subtract the mean first (two passes) or use Welford's method.

🧠

Log-sum-exp and softmax

log⁡∑ezi\log\sum e^{z_i}log∑ezi​ is computed as m+log⁡∑ezi−mm + \log\sum e^{z_i - m}m+log∑ezi​−m with m=max⁡zim = \max z_im=maxzi​: no overflow, no loss of digits.

🔊

Audio in decibels

Speech energy in dB uses 10log⁡10(E+ϵ)10\log_{10}(E + \epsilon)10log10​(E+ϵ); the small ϵ\epsilonϵ stops log⁡0\log 0log0 on silent frames.

💰

Money

Banks never store taka as binary floats: 0.1 is inexact. They use integers (paisa) or decimal arithmetic.

Summary

Key points
  • Ea=∣x−x∗∣E_a = |x - x^*|Ea​=∣x−x∗∣, Er=Ea/∣x∣E_r = E_a/|x|Er​=Ea​/∣x∣, Ep=100ErE_p = 100E_rEp​=100Er​; correct to nnn significant digits if Er≤12101−nE_r \le \tfrac12 10^{1-n}Er​≤21​101−n
